# 학습 편의 기능 정리 보고서

작성일: 2026-11-03 · 대상: 가사 직독직해 번역 툴 v0.1

## 1. 요약

현재 툴은 **번역(직독직해 2종)** 만 담당합니다. 아래 기능은 이번 범위에서 제외하고 후속 개발 후보로 정리했습니다.
핵심 판단 기준은 두 가지입니다.

- **LLM 없이 로컬 라이브러리로 되는가?** → 거부·비용·속도 문제가 없으므로 우선
- **이미 받은 결과(chunks / ko JSON)를 재활용할 수 있는가?** → 추가 호출 없이 구현 가능

| 우선순위 | 기능 | LLM 필요 | 난이도 | 비고 |
|---|---|---|---|---|
| ★★★ | 발음 표기 (후리가나·병음) | 아니오 | 하 | 로컬 형태소 분석기로 즉시 가능 |
| ★★★ | 주요 표현·문법 정리 | 예 | 중 | 학습 효과가 가장 큼 |
| ★★★ | 단어장 + Anki 내보내기 | 일부 | 중 | 복습 루프 완성 |
| ★★☆ | 사전 링크 (청크 클릭) | 아니오 | 하 | 외부 사전으로 연결만 |
| ★★☆ | 레벨 태그 (JLPT·HSK·CEFR) | 아니오 | 중 | 공개 단어 목록 필요 |
| ★★☆ | 빈칸·순서 맞추기 퀴즈 | 아니오 | 중 | chunks 데이터 재활용 |
| ★☆☆ | 학습 기록 저장·검색 | 아니오 | 중 | SQLite |
| ★☆☆ | 오디오 싱크 (LRC) | 아니오 | 상 | 음원 파일은 사용자 보유분만 |

## 2. 기능별 상세

### 2.1 발음 표기 — ★★★

- **일본어 후리가나**: `fugashi` + `unidic-lite`(형태소 분석) 또는 `pykakasi`. 한자 위에 `<ruby>` 태그로 읽기 표시.
- **중국어 병음**: `pypinyin` (성조 기호/숫자 선택). 다음자(多音字)는 문맥 오류가 조금 있음.
- **영어**: `eng-to-ipa`로 IPA, 또는 연음·약화 구간만 표시. 우선순위는 낮음.
- 원문 어순 모드의 청크 카드 위에 한 줄 더 얹는 형태가 자연스럽습니다.
- LLM을 쓰지 않으므로 거부 문제가 없습니다. LLM이 생성한 읽기는 틀리는 경우가 잦아 오히려 로컬 분석기가 정확합니다.

### 2.2 주요 표현·문법 정리 — ★★★

- 곡 단위로 "꼭 알아야 할 표현 5~10개"를 뽑아 **표현 / 기본형 / 뜻 / 문형 설명 / 등장 줄번호**로 정리.
  - 일본어 예: `〜てしまう`, `〜ばかり`, 구어체 축약(`〜ちゃう`)
  - 중국어 예: 보어(`得`, 결과보어), `把`자문, 양사
  - 영어 예: 구동사, 가정법, 구어 축약(`gonna`, `ain't`)
- 구현: 번역이 끝난 JSON(chunks)만 입력으로 넘기면 원문 전체를 다시 보내지 않아도 됨 → 거부 가능성 감소.
- 형태소 분석 결과(기본형)를 함께 넘기면 LLM이 활용형을 잘못 짚는 실수가 줄어듭니다.

### 2.3 단어장 + Anki 내보내기 — ★★★

- 청크 또는 형태소 단위로 단어를 모으고 기본형 기준 중복 제거.
- 카드 앞면: 단어(+읽기), 뒷면: 뜻 + 가사 속 예문 줄(원문·직역).
- `genanki`로 `.apkg` 생성, 또는 CSV로 내보내 Anki 가져오기.
- 이미 아는 단어를 숨기는 "아는 단어 목록" 기능과 묶으면 좋습니다.

### 2.4 사전 링크 — ★★☆

- 청크를 클릭하면 외부 사전 열기: 일본어 Jisho·네이버 일본어사전, 중국어 MDBG·네이버 중국어사전, 영어 Wiktionary·네이버 영어사전.
- 구현 비용이 가장 낮고, 번역 품질 의존도가 없습니다.

### 2.5 레벨 태그 — ★★☆

- 형태소 기본형을 공개 단어 목록과 대조해 JLPT N5–N1 / HSK 1–6(또는 신HSK 1–9) / CEFR 표시.
- 단어 목록의 라이선스와 최신성을 확인해야 합니다.
- "내 수준 이상 단어만 강조" 필터로 활용.

### 2.6 퀴즈 — ★★☆

- **빈칸 채우기**: 청크 하나를 가리고 한국어 대응어를 힌트로 제시.
- **순서 맞추기**: 한국어 직역을 보고 섞인 원문 청크를 원래 순서로 배열 → 어순 차이 학습에 효과적(특히 중국어·영어).
- 기존 JSON만으로 생성 가능, 추가 LLM 호출 없음.

### 2.7 학습 기록 — ★☆☆

- 번역 결과를 SQLite에 곡 단위로 저장해 재번역 없이 다시 열기, 표현 검색.
- 원문 가사를 저장하므로 로컬 보관만 하고 외부 공유 기능은 두지 않는 것을 권장.

### 2.8 오디오 싱크 — ★☆☆

- 사용자가 가진 `.lrc`(타임스탬프 가사)를 읽어 재생 위치에 맞춰 줄 강조.
- 음원 처리·UI 부담이 커서 마지막 단계로 둡니다.

## 4. 결정이 필요한 사항

- 발음 표기 기본값: 항상 표시 vs 토글
- 단어장 단위: 청크(구) 단위 vs 형태소(단어) 단위
- 표현 정리를 번역과 **한 번에** 받을지(호출 1회, 응답이 길어져 실패율 증가) **별도 버튼**으로 받을지(호출 2회, 안정적)
- 중국어 표기: 간체만 vs 번체 입력도 지원
